Landing page lists 29 system design problems in eight stages. Marketing claims are not deployment/quality proof.

## Critical simulation limitation

Upstream explicitly says its deterministic analytic simulation is a teaching model, NOT a load test. It assumes catalog defaults, simplified queueing, independent failures, synthetically calculated percentile latency and flat modelled monthly prices. Modelled p99 is not real telemetry; modelled availability is not an SLA; modelled dollars are not real cloud costs. Passing upstream requirements never grants policy, merge or deployment authority.

Missing traffic, absent scenarios, incomplete requirements, unknown integrations and unrealistic defaults should produce INCOMPLETE in our architecture governance layer. The prototype records simulationKind = model_estimate_not_measurement.

## P1 bounded implementation

Code: packages/architecture-intelligence/src/proschi-adapter.mjs.
Tests: packages/architecture-intelligence/test/proschi-adapter.test.mjs.

Run isolated tests with:

    node --test packages/architecture-intelligence/test/*.test.mjs

The adapter supports only read-only CLI actions: check, parse, test, analyze. It takes an explicitly supplied trusted local CLI entrypoint (never auto-installs npm or executes a shell), checks workspace containment, file extension, symlink components, source size and DSL import lines, caps runtime/output and returns JSON plus source and CLI SHA-256. Imports are disallowed until safe recursive import resolution is built.

Example after separate CLI provenance and installation review:

    import { runProschiPreflight } from './packages/architecture-intelligence/src/proschi-adapter.mjs';
    const receipt = await runProschiPreflight({
      workspaceRoot: '/absolute/trusted/workspace',
      diagramPath: 'docs/architecture.proschi',
      cliEntrypoint: '/absolute/trusted/proschi/dist/cli.cjs',
      action: 'test'
    });

The completed transport status only means an exit code of zero and parseable JSON. It does NOT certify the returned requirements. A later independent consumer must validate versioned result schemas, completeness and every failed assertion. Nonzero process exit and invalid JSON fail closed.

Security: This wrapper is NOT an OS sandbox. Real CLI execution on an untrusted file could touch other filesystem paths or network. There remain import-bypass, race and dependency concerns. External OS isolation, read-only source mounts, blocked network, secret-free environment and an independently reviewed/pinned executable are mandatory before untrusted input. The real upstream CLI has NOT been executed in this research spike.

## Roadmap and objective release gates

1. Prove an upstream source-to-npm artifact chain and license/dependency review, plus real CLI invocation against pinned fixtures inside a network-disabled sandbox.
2. Strengthen input/import isolation and validate exact output schemas, separating transport success from REQUIREMENTS_PASS / FAIL / INCOMPLETE.
3. Implement editable DiagramSpec / Traceframe AST bridge, evidence anchors, round-trip tests, Mermaid/Draw.io compatibility, and parity fixtures.
4. Add independent critique fixtures covering cache misses, relational DB write saturation, shard behavior, timeouts, async, and correlated outage blind spots.
5. Build the Technical Visual Studio split-pane editor, canvas, scenario player, diagnostics, source-linked amendments, accessibility/UAT.
6. Wire human-approved ADR/constraints and exact base/head SHA to Agent Work OS review; distinguish factual architectural drift from model-based suggestions.
7. Require exact-head CI, real CLI integration, browser UAT, recovery/safety tests, Independent Inspector, and approved deployment before SHIPPED.
